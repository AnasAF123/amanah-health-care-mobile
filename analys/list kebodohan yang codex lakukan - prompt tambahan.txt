**Pola yang terlihat:**
- Setiap kali Codex memanggil file **`.bat`** (`dart.bat format`, `dart.bat analyze`, `flutter.bat test`) → hasilnya selalu `(no output)`, harus di-poll berkali-kali, akhirnya dihentikan paksa.
- Begitu Codex memanggil **`.exe` langsung** dari `bin\cache\dart-sdk\bin\dart.exe` (bypass wrapper `.bat`) → `format` selesai dalam 0.17 detik, `analyze` juga langsung selesai dengan output bersih.

Ini indikasi kuat bahwa masalahnya ada di **wrapper `.bat`**, bukan di command itu sendiri atau di ukuran repo. Ada beberapa kemungkinan penyebab spesifik kenapa `.bat` hang di sandbox eksekusi Codex:

1. **Version/update check yang butuh jaringan.** `flutter.bat` (dan `dart.bat` versi lama) melakukan pengecekan versi/channel — kadang lewat `git fetch` ke remote SDK, kadang lewat request analytics/telemetry. Kalau sandbox Codex membatasi domain outbound (sangat umum untuk CLI agent), request ini bisa *hang* alih-alih gagal cepat dengan error jelas.
2. **`flutter test` khususnya butuh artifact tambahan** — mesin `flutter_tester` untuk headless widget test. Kalau belum ter-cache di mesin ini, Flutter akan mencoba download dari Google Cloud Storage. Kalau domain itu tidak masuk allowlist jaringan sandbox, prosesnya diam tanpa error, persis gejala yang muncul.
3. **Prompt interaktif first-run** (consent analytics) yang menunggu input di stdin — di sesi non-interaktif, ini nge-block selamanya karena tidak ada yang bisa menjawab.
4. **`.bat` sendiri men-spawn `cmd.exe` bersarang** — kalau harness eksekusi shell Codex tidak mengalokasikan console/pty yang proper, proses child bisa stuck menunggu handle yang tidak pernah beres.

**Soal "paradigma"-nya — ya, ada yang bisa dikritik dari cara Codex menangani ini:**

- Codex mengulang pendekatan yang sama (macam-macam quoting untuk `.bat`) **4-5 kali** sebelum akhirnya coba `.exe` langsung — cukup boros trial-and-error padahal pola kegagalannya sudah konsisten sejak percobaan kedua.
- Yang lebih penting: setelah `dart.exe` langsung terbukti jadi solusinya untuk `format`/`analyze`, Codex **tidak menerapkan fix yang sama ke `flutter test`**. Dia cuma coba `flutter.bat` lagi, hang, lalu menyerah dan melaporkan `dart analyze` sebagai "validasi yang cukup". Padahal `dart analyze` cuma menangkap error tipe/compile-time — bukan bug behavior runtime di widget yang baru dipatch (blur layer, carousel snap, dsb). Jadi klaim "validasi berhasil" di ringkasan akhir itu agak menyesatkan: **test widget yang sebenarnya belum pernah benar-benar jalan.**
- Codex juga tidak pernah membedakan "proses masih jalan lama" vs "proses sudah exit tapi outputnya kosong/di stream lain" — tidak ada `2>&1` untuk menangkap stderr, tidak ada exit code yang dicek eksplisit.

**Saran praktis kalau mau lanjut mengejar root cause:**
- Coba jalankan `flutter test` manual di terminal biasa (bukan lewat agent) — kalau memang nyangkut di prompt analytics atau download artifact, akan kelihatan langsung.
- Jalankan sekali `flutter config --no-analytics` dan `flutter precache` secara manual supaya first-run prompt/download tidak lagi jadi penghalang saat dipanggil dari agent.
- Kalau memang root cause-nya jaringan terbatas di sandbox Codex, cek apakah Codex punya pengaturan allowed-domains (mirip yang saya punya) dan tambahkan domain artifact Flutter (`storage.googleapis.com` dkk) atau jalankan test di luar sandbox.
- Sebagai workaround cepat: coba pola yang sama seperti `dart.exe` — cari snapshot `flutter_tools` dan panggil lewat `dart.exe` langsung, bypass `flutter.bat` sepenuhnya.

  Alasan mengapa efek glass mask di Flutter sering terlihat crisp (tepi kaku/patah) atau harsh adalah karena developer biasanya hanya
  membungkus BackdropFilter dengan ClipRect standar tanpa melakukan alpha gradient masking atau progressive blur.
  Di web/CSS (glass-mask.jsx:41-58), efek liquid blur tersebut dihasilkan dari kombinasi:

  1. backdropFilter: 'blur(20px) saturate(160%)'
  2. maskImage: linear-gradient(...) (melunakkan batas blur secara bertahap)
  3. Ambient gradient overlay (menjaga kontras teks tanpa milky haze).
  ──────
  ### Library yang Dibutuhkan di Flutter

  Sebenarnya Anda tidak wajib menginstall library pihak ketiga karena Flutter sudah menyediakan widget bawaan engine (Skia / Impeller) yang
  sangat powerful. Namun ada opsi library jika ingin fitur shader tingkat lanjut:

   Pendekatan                               | Library / Package               | Kapan Digunakan
  ------------------------------------------|---------------------------------|-------------------------------------------------------------
   Native Flutter (Sangat Direkomendasikan) | flutter/material.dart + dart:ui | Cukup gunakan ShaderMask + BackdropFilter +
                                            |                                 | ColorFilter.matrix. Zero-dependency, performa 60–120 FPS
                                            |                                 | native.
   Shader Khusus (True Variable Blur)       | flutter_shaders[1]              | Jika butuh progressive variable blur (sigma blur membesar
                                            |                                 | dinamis per-pixel via custom GLSL/SPIR-V fragment shader
                                            |                                 | seperti di iOS).
   Helper Utility                           | blur[2] atau glassmorphism[3]   | Jika ingin wrapper ringkas, namun untuk masking liquid
                                            |                                 | tetap perlu kombinasi ShaderMask.

  [1]: flutter_shaders https://pub.dev/packages/flutter_shaders
  [2]: blur https://pub.dev/packages/blur
  [3]: glassmorphism https://pub.dev/packages/glassmorphism
  ──────
  ### Kunci Agar Mask Liquid Tidak Crisp & Menyatu Halus

  1. ShaderMask dengan BlendMode.dstIn: Berfungsi persis seperti mask-image: linear-gradient(...) di CSS. Bagian hitam gradien
  mempertahankan blur, sedangkan bagian transparan memudarkan efek blur secara lembut ke foto asli.
  2. Matrix Saturation: CSS saturate(160%) direplikasi menggunakan ColorFilter.matrix pada level filter agar warna di balik kaca tetap
  pop/vibrant (tidak pucat/pudar).
  3. ClipRRect Outer Boundary: Mencegah blur bleeding keluar dari sudut rounded card 32px.
